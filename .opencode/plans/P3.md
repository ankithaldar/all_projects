# P3 Time-Split Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Each task below is independently assignable, testable, and file-disjoint. Workers read their task section only, plus `contracts.md` for their contract.

I'm using the writing-plans skill to create the implementation plan. (Product-planner autonomous mode: planned to Lead only via the blackboard; no direct user dispatch.)

**Goal:** Implement P3 Time-Split on top of the frozen P1 temporal core (`temporal_split` + `assert_no_leakage` + `presplit` raise, D-TEMPORAL-SPLIT-1) — purged-CV folds, walk-forward backtesting harness, embargo/overlap guards, calibrate-prohibition charter + enforcement, and time-series split integration into `data_prep`/`modeling` pipelines — with full implementations only (no stub exits) and leakage tests that re-prove the frozen invariants including the 100-row 73/20/7 trace and purged-folds no-overlap.

**Architecture:** P3 is pure-Python ML-split work only. New logic lives in two small new modules (`pipelines/modeling/purged_cv.py`, `pipelines/modeling/backtest.py`) so it cannot perturb frozen boundaries; existing-file edits are additive only (assignment helper + guards + calibrate guard in `data_split.py`/`calibration.py`; pipeline wiring + default params in `data_prep`/`modeling` pipelines). Every split path funnels through frozen `assert_no_leakage` (single strict formula `max_time_train < min_time_test - embargo`) and the single assignment helper `_temporal_fold_assignment` in `data_split.py` (P3-C, single owner — see §4.8-compliance decision below); a P3 plan that embeds its own ordering/embargo arithmetic in `purged_cv.py`/`backtest.py` instead of calling that helper is a gate failure (§4.8). Single splits still call frozen `temporal_split` directly.

**§4.8-compliance decision (chosen: Option B — named helper in `data_split.py`; stated once, applied in P3-A/P3-B/P3-C):** Purged folds are built by per-fold calls to `_temporal_fold_assignment(df, *, time_col, test_start, n_test_block, embargo, purge)` exposed from `data_split.py` (P3-C owns `data_split.py`; P3-A imports the helper read-only and contains no ordering/embargo arithmetic). Alternatives considered and rejected: (A) per-fold `temporal_split` calls on prefixes — rejected because `temporal_split` returns only train/test (embargoed rows are not returned, so the full sorted prefix cannot be reconstructed without a second sort outside `data_split.py`) and `ceil(test_size * len(prefix))` does not in general reproduce `n_test_block` exactly, so fold geometry would drift by rounding; (C) amending §4.8 gate language in `contracts.md` to charter a purged assignment — rejected because this planner owns `.opencode/plans/P3.md` only and cannot amend `contracts.md` §4.8 (that would require a `solution-architect` ADR + gate outside P3 scope). The helper reuses the frozen ordering path (`_check_no_mixed_tz`, stable sort, `_parse_embargo`, `_embargo_str`, `_parse_meta_time`) inside its single owner file and is pinned to `temporal_split` by the 100-row 73/20/7 golden in both P3-C and P3-A tests (see P3-C/P3-A Acceptance). Grep guards in P3-A/P3-B are updated for this decision: `purged_cv.py`/`backtest.py` must import `_temporal_fold_assignment` (via `purged_cv_folds`) / `purged_cv_folds` respectively and must contain no `sort_values`, no `_parse_embargo`, no `train_end`, and no second leakage-formula string outside the helper's owner file.

## Review Focus (five failure modes most likely to bite — each pinned to an owning task's test)

1. **A purged fold quietly leaks** (fold test head overlaps fold train time, purge gap < embargo, duplicate timestamps at the fold horizon, or folds share row indices). → P3-A via the P3-C helper: per-fold `assert_no_leakage` on `fold_meta` with `embargo = max(embargo, purge)` (purge enforced by the checked field) + `assert_no_overlap` on the full fold list; 100-row folds trace asserts `n_train+n_embargoed+n_purged+n_test == test_start+n_test_block` per fold and pairwise test-index disjointness + time-increasing test blocks; purge>embargo counts pinned (`n_train=70, n_embargoed=7, n_purged=3` for embargo 7d/purge 10d, see P3-A).
2. **A backtest rung silently passes through a bad fold** (empty fold, `model_fn` returning `None`, `predict` returning `None`/wrong shape, metric raising but caught, or a stub `return {}` on the first rung). → P3-B: every rung either scores or raises; `model_fn(train_df)` is refit per fold and scored as `predict(test_df[feature_cols])` vs target with exact scores pinned (`-43.5` / `-53.5` / aggregate `-48.5` for the train-mean regression fixture, see P3-B); `None`/shape-mismatch raises `ValueError` (no placebo aggregate), plus an empty-input rung raises.
3. **A leaky presplit or mixed-tz column reaches modeling** (data_prep default split stays stratified/shuffled while params claim `temporal`, or naive/aware mixes surface as `TypeError` in a fold). → P3-D: `split_raw_data_with_meta` with nested `sampling_params.method='temporal'` and no `time_col` raises `ValueError` (not stratified fallback); mixed-tz raises `ValueError` naming `_check_no_mixed_tz` through the full pipeline path; leaky presplit raises via `split_presplit_data`.
4. **Calibration with temporal split silently runs** (the deferred prohibition is recorded in meta only, so a sigmoid calibration fits on future data and inflates the backtest). → P3-C: `calibrate_model` detection tests ALL real signals (`params.method`, `params.sampling_params.method`, `split_meta.sampling_method`, `raw_sampling_method`, `raw_requested_method`, aliases `{temporal, time, ordered}`, effective calibration method after handle resolution including the `BetaCalibration` handle override) and with effective method != `'none'` + `allow_temporal=False` raises `ValueError`; with `allow_temporal=True` it proceeds and meta `temporal_calibration_allowed` is always present as a `bool` (`True` only when the exception is actually used). P3-D proves the same guard fires on the real presplit shape (`sampling_method='presplit'`, `raw_sampling_method='time'`, nested `sampling_params.method`).
5. **Embargo shrinks the final test fraction** (a naive cut-then-drop returns 27/100 instead of 20/100, or fold test sizes drift). → P3-A + P3-C: post-embargo fraction pinned by the 100-row 73/20/7 test (P1-B1 golden re-asserted verbatim in P3 suites, including via `_temporal_fold_assignment`) and per-fold `len(test)/N == test_size ± 1/N`.

## Problem

P1-B1 implemented the frozen temporal core (`temporal_split`, `assert_no_leakage`, fail-closed `presplit`) but deferred purged-CV folds and calibrate prohibition to P5/P7 (B4(c)). Without a file-disjoint P3 plan, P4/P5 would each invent fold/backtest logic (Top-5 #2: default split is stratified+shuffled, every unspecified config is a leakage config; Top-5 #3: no group/entity split) and P0-C would persist (presplit bypass: data_prep's non-temporal split can never be recovered by modeling presplit). P3 closes the loop: one purged-CV definition, one walk-forward harness, one guard set, pipeline wiring that makes `method='temporal'` the only honest path — so P4 feature eng and P5 supervised baselines inherit a single leakage definition.
