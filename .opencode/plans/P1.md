## Review Focus (five failure modes most likely to bite — each pinned to an owning task's test)

1. **A buggy reader accepts a half-v2 artifact** (e.g. `version=2` + `schema=fitted_registry.v1`, or flat+nested step duplication) and silently scores with wrong statistics. → P1-A1: internal-consistency test (mixed meta raises; writer emits nested `steps` only, never flat duplicates); `read_registry` returns `steps_dict` (see ADR note).
2. **A calibrated envelope cannot round-trip** because its `_SAFE_GLOBALS` are missing, or the raw estimator is confused with the adapter/dict at `log_model`. → P1-A2 + P1-D1: calibrated `restricted_loads` round-trip (sigmoid + isotonic + betacal, pickletools residual exactly 7 tuples) and mocked `log_model(tags=...)` capture (never run-level `set_tags`).
3. **A "temporal" split quietly leaks** (equal boundary timestamps, mixed naive/aware tz, or embargo shrinking the final test fraction; leaky presplit silently annotated). → P1-B1: strict `max_train < min_test - embargo` invariant, mixed-tz `ValueError` (not `TypeError`), `presplit` runs `assert_no_leakage` and **raises** on leak, and 100-row post-embargo fraction test (`len(test)==20`, `n_embargoed==7`).
4. **Erasure appears to work but leaks PII** (clear subject ID in report/audit/logs, `mask_pii` via secret-only scrub leaves email/user_id/device_id, second scrubber drift, Redis memory-only crash from unconditional `delete`, `mask_pii` undeclared passthrough). → P1-D1: deterministic REDACTED/hash `mask_pii` + substring test, conditional-Redis test (fake client with `get/set/delete` + memory-only `_client() is None` path + error-propagation + re-read), clear-ID string-search via scrub leaf over report+audit+caplog, grep guard for single `subject_hash` across ALL new modules, fail-closed write guard calling `detect_pii`.
5. **Quarantine / lineage / catalog silently pass bad rows or collide** (GX failure dropped on the floor / silently consumed with `quarantine_enabled=False`, lineage records run-level only, duplicate catalog key, banner not load-observable). → P1-C: quarantine-split invariant (`len(clean)+len(quarantine)==len(df)`, `ValidationResult.failing_row_ids`/`failing_mask` drive the split, `require_clean` raises, no silent consume) · P1-E: `catalog_banner_map` load-observable helper + no-`best_model_onnx` catalog test + column-level lineage test (not run-level only).

## Problem

P0 froze *what* the contracts are (fitted_registry v2 dual-read, best_model v2 dict, temporal split, secrets/retention/PII/GDPR, ONE-catalog grouping) but wrote no product code. Without a file-disjoint P1 implementation plan, P2 IaC would provision from unfrozen bytes and P3 would re-invent split logic per caller, reproducing the leakage and Hyrum's-Law hazards documented in contracts.md and edge-cases.md (F5/F6/P0-B/P0-C).

## User stories (Lead / downstream consumers)

- As a **Lead**, I want P1 tasks that are file-disjoint with machine-checkable Done so I can dispatch P1 workers in parallel without merge collisions, so that P2 entry is never blocked by a half-landed contract.
- As a **P3 time-split consumer**, I want a single `temporal_split` + `assert_no_leakage` implementing the frozen strict formula so that no caller can ship a leaky split by choosing different spellings, so that leakage is a test failure, not a metric surprise.
- As a **modeling/scoring engineer**, I want dual-read `fitted_registry` (v1 readable, v2 writable, unknown versions fail loud) and a `best_model` dict envelope with a single `unwrap_envelope` so that v1 artifacts keep scoring while v2 artifacts are self-describing, so that upgrades never silently change fitted statistics.
- As a **security reviewer**, I want one scrub leaf, one `subject_hash`, deterministic REDACTED/hash `mask_pii`, conditional+error-propagating Redis delete, hashed-only logs/audit/consent, and fail-closed PII writes so that GDPR erasure is auditable end-to-end (rows deleted, artifacts flagged, clear IDs never logged), so that a second scrubber or hash helper is a gate failure.
- As a **data platform operator**, I want GX validation with an explicit quarantine split driven by failing-row IDs and fail-closed consumption plus column-level lineage plus a grouped catalog so that failed-expectation rows are routed, not dropped, and every output column traces to its source, so that quality failures are visible and attributable.
