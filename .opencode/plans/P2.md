# P2 Platform / IaC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Each task below is independently assignable, testable, and file-disjoint. Workers read their task section only, plus `contracts.md` for their contract.

I'm using the writing-plans skill to create the implementation plan. (Product-planner autonomous mode: planned to Lead only via the blackboard; no direct user dispatch.)

**Goal:** Deliver P2 platform **production-readiness** (container + K8s/Helm, Azure parity, observability, alert routing, OIDC/RBAC migration, secrets out-of-band wiring) consuming P0-frozen / P1-implemented contracts with zero frozen-semantics changes — readiness ≠ promotion (P11 only, D-MVP-READINESS-1).

**Architecture:** P2 is IaC + thin platform Python only. ## Global Constraints (apply to every P2 task)

- Strict formatting standard applies to all Python code in P2 (SOLID, Google docstrings, 2 spaces, single quotes, `.pylintrc` read-only, shebang header, max-line-length=80)
- Python formatting detail (normative for P2-AU1, P2-S1 and any Python test/helper): SOLID (Single Responsibility, Open/Closed, Liskov, Interface Segregation, Dependency Inversion — small focused modules, inject collaborators, never duplicate P1 surfaces); Google-style docstrings on every module/function/class (Args/Returns/Raises sections where applicable); 2-space indentation (`indent-string='  '` per `.pylintrc` `[FORMAT]`); single quotes for all strings (`check-quote-consistency=yes`, single-quote default); max-line-length=80 (no line exceeds 80 characters in P2 Python; CI gate `awk 'length>80' <touched .py files>` must be empty — this freezes the 80-column limit for all P2 Python); `.pylintrc` read-only (workers must never edit `.pylintrc`; CI runs `pylint --rcfile=.pylintrc --fail-under=9.0`).
- No contract edits: P2 workers must not edit `.opencode/plans/contracts.md`, `.opencode/context/decisions.md`, or any frozen `src/` semantics (`pipelines/data_prep/fitted.py`, `pipelines/modeling/envelope.py`, `pipelines/modeling/data_split.py`, `governance/scrub.py` sole leaf, `governance/pii.py`, `governance/retention.py` pure `check_retention`, `governance/erasure.py`, `core/artifact_store.py` allowlist). Consume those surfaces read-only; if a task appears to need a frozen-semantic change, stop and raise `BLOCKED:` to Lead (new ADR + gate required).
- No residency pin: per D-SECRETS-PII-GDPR-1 §5.2(e), P2 pins no region/residency claim. Terraform `region`/`location` are variables with no hard residency guarantee; artifacts created before the P11 decision carry no residency guarantee. Never add a region literal that implies a residency commitment; document the variable as non-binding.
- No in-repo rotation code: per D-SECRETS-PII-GDPR-1 §5.2(e), secret rotation is out-of-band via cloud. P2 adds no rotation code, no rotation schedule, no in-repo key material, no `rotate`/`refresh` helper. Secrets wiring is env-only (`GOOGLE_APPLICATION_CREDENTIALS`, `AWS_PROFILE`, `MODEL_SHA256`/`FORECAST_MODEL_SHA256`, `FORECAST_OIDC_*` via env) with Terraform references to Secret Manager / Key Vault / Secrets Manager mounts only.
- No secret values in repo: no secret token value may appear in YAML, Terraform `*.tfvars` (committed), Helm `values.yaml`, Dockerfile, or docs. Terraform reads secret *references* (secret IDs, vault names) via variables/outputs; Helm/K8s reads via env/Secret mounts. Grep guard: `grep -R 'sk-[a-zA-Z0-9]\|AKIA[0-9A-Z]\{16\}\|xox[bap]-' forecast_ml_framework/infra forecast_ml_framework/deploy` must return empty.
- No production promotion: completing P2 proves readiness (build/deploy/observability criteria met); it does not authorize production traffic, model promotion, or release per D-MVP-READINESS-1. No task may enable serving traffic beyond readiness checks, flip a `production` alias, or claim "production" status before P11 exit. `production = true` Terraform validations that block empty CMEK (GCP/AWS precedent) stay as-is; P2 adds no `production=true` apply.
- TDD mandatory: RED test commit first, then GREEN, then REFACTOR. For config-only tasks, RED = validation/lint failure on missing file or bad value (e.g. `helm lint` fails, `terraform validate` fails on unknown resource); GREEN = validation green with the new file. Every task leaves RED→GREEN evidence in `.opencode/handoffs/P2-<task>.md`.
- **Single coverage gate definition (sole definition — all per-task commands below reference this name and never redefine it):** per-task Python gate = `pytest --cov=<exact-module> --cov-fail-under=85 <exact-test-file> -q` where `<exact-module>` is the full import path without `src.` prefix (e.g. `forecast_ml_framework.serving.auth`) and `<exact-test-file>` is the task's `tests/test_p2_*.py` path. For config-only tasks (P2-C1/I1/O1/O2/R1 with no new Python module), the gate is the named validation command (`terraform validate`, `helm lint`, `amtool check`, `kubeconform` where specified) — no per-task Python coverage is claimed. Full-suite check = `bash forecast_ml_framework/ci/run_checks.sh` (extends the P1 8-file suite + new P2 tests; see § Exit criteria). `pylint --rcfile=.pylintrc --fail-under=9.0 forecast_ml_framework/src` must stay green for Python tasks.
- Additive only: P1 v1 artifacts must keep working; auth migration keeps dev-mode unauthenticated behavior only when `FORECAST_API_KEY` unset **and** OIDC unconfigured (see P2-AU1) — never silently downgrades OIDC failures to API-key or unauthenticated. Unknown OIDC issuer/audience fails closed (401, not 500, not allow).
- File-disjoint: no file appears in two tasks' `Owns:` (see § File footprint matrix). Parallel workers run in separate worktrees; merge via Lead / `devops-sre`. Shared-file collisions are planning bugs — if you need another task's file, stop and raise `BLOCKED:` to Lead; do not edit it.
- Catalog-driven paths: IaC provisions storage paths from catalog `filepath` values only (contracts §1.6); never hardcode a storage path in Terraform/Helm that contradicts `conf/base/catalog.yml` or `conf/azure/catalog.yml`. Where a bucket/vault name is a Terraform variable, its default must match the catalog filepath bucket (see infra/README.md parity table).
- File-disjoint IaC: GCP/AWS existing `infra/{gcp,aws}/main.tf` is never edited in P2. New Terraform lives in disjoint files (`infra/azure/*`, `infra/{gcp,aws}/secrets.tf`) so P2-S1 and P2-I1 cannot collide on the same `*.tf` file. Existing `infra/{gcp,aws}/variables.tf`/`outputs.tf` are never edited either (see matrix).

## Review Focus (five failure modes most likely to bite — each pinned to an owning task's test)

1. **A container that cannot run the serving app** (missing dep, wrong entrypoint, no non-root, health probe wrong) ships as "ready". → P2-C1: `docker build` + `helm lint` + `kubectl rollout status` + real `GET /health` 200 from the running image (frozen `uvicorn forecast_ml_framework.serving.app:app --host 0.0.0.0 --port 8000` entrypoint + `uv sync --frozen --no-dev` install step) pinned in `test_p2_container_deploy.py`.
2. **Azure parity that looks identical but leaks the network** (public storage, no private endpoint, Entra audience mismatch, vault secret in state) → P2-I1: `terraform validate` + `terraform plan` shows private endpoints + VNet + NSG deny-public, `public_network_access_enabled=false`, private DNS zones, Entra `audience` equals API base URI. Pinned in P2-I1 acceptance.
3. **Dashboards that never fire because drift/alert wiring is unwired** (metric name mismatch, NaN-never-alerts M8 hole, Slack/PagerDuty webhook missing) → P2-O1/O2: alert syntax + stub firing only in P2 (no production metric claim — the app `/metrics` producer is not frozen in P2; synthetic-drift fixture proves the Alertmanager rule syntax fires against a stub metric, `amtool` green). Pinned in P2-O1/P2-O2 acceptance.
4. **OIDC migration that silently falls back to the shared key or logs the token** (Bearer fallback, alg confusion, clear `jti`/`sub` in logs, revocation not enforced) → P2-AU1: OIDC roundtrip test (valid token 200, expired/revoked/wrong-audience 401), alg=`RS256` only, no token in access/audit logs (string-search assertion via scrub leaf), per-`jti`/`sub` revocation list check, fail-closed startup on partial `FORECAST_OIDC_*`. Pinned in `test_p2_oidc_auth.py`.
5. **Secrets/retention wiring that looks wired but is not** (secret value committed, rotation code smuggled in, cron never calls `enforce_retention`, residency pinned by accident) → P2-S1: grep guards (no secret value, no `rotate` code, no region literal implying residency), retention-job integration test (expired fixture swept via `enforce_retention`, audit entry hashed). Pinned in `test_p2_retention_job.py` + P2-S1 grep guards.

## Problem

P0 froze *what* the contracts are and P1 implemented them (fitted dual-read, temporal split, envelope, allowlist/delete/PII, catalog, retention/erasure), but no deployable runtime exists: `serving/app.py` docs say "No Docker is provided", infra covers GCP+AWS only (no Azure VNet/private-endpoint/Entra parity), there is no OTel/Prometheus/Grafana stack, no Slack/PagerDuty routing, auth is a single shared `FORECAST_API_KEY` with all-or-nothing revocation (app.py:41-46 audit limits, M3 extraction), and retention/erasure has no scheduled caller. Without a file-disjoint P2 platform plan, P3+ would build ML capability on unprovisioned, unauthenticated, unobserved infra and P11 could not judge readiness.

## User stories (Lead / downstream consumers)

- As a **Lead**, I want P2 tasks that are file-disjoint with machine-checkable Done so I can dispatch P2 workers in parallel without merge collisions, so that P3 entry is never blocked by a half-landed Helm chart or Terraform stack.
- As a **serving consumer**, I want a Docker image + Helm/K8s deploy with probes and a rollback drill so that every deploy is reproducible from a chart, not a manual host, so that readiness is a `kubectl` check, not a hope.
- As a **security reviewer**, I want OIDC/JWT + RBAC with per-principal revocation and secrets wired env-only out-of-band (no rotation code, no secret values in repo, no residency pin) so that the shared-key blast radius and the in-repo-rotation/residency hazards are closed without inventing a second scrubber or hash helper.
- As a **platform operator**, I want Azure parity (VNet, private endpoints, Entra OIDC, Key Vault), OTel/Prometheus/Grafana, and Slack/PagerDuty alert routing with synthetic-drift firing proof so that "ready" means a dashboard moves and an alert pages when I inject drift, so that P11 has evidence, not assertions.

- CI + runbook (P2-R1): extend CI (`forecast-ml-ci.yml`) and `ci/run_checks.sh` to `terraform validate` green for **gcp+aws+azure**, add `helm lint` + `amtool check` gates, wire the K8s deploy + rollback drill into CI (kind/k3d or template-only where no cluster exists, with fallback evidence), and ship a P2 runbook (`docs/runbook-p2.md` + `deploy/README.md`) covering deploy/rollback, OIDC rotation (out-of-band), alert firing, and retention/erasure operations.
